# Metodologia

O projeto será desenvolvido individualmente utilizando uma metodologia ágil, buscando dividir o desenvolvimento do sistema em pequenas tarefas, que serão organizadas e acompanhadas por meio de um quadro Kanban. O projeto permitirá alterações em seus requisitos e ferramentas ao longo do processo de desenvolvimento, conforme novas necessidades sejam identificadas.

Toda a documentação do projeto será mantida neste repositório.

## Controle de Versão

A ferramenta de controle de versão adotada no projeto é o [Git](https://git-scm.com/), enquanto o [GitHub](https://github.com) será utilizado para hospedagem do repositório e gerenciamento do projeto.

O projeto segue a seguinte convenção para o nome das branches:

- `main`: versão estável e testada do software.
- `dev`: versão de desenvolvimento do software.
- `feature/*`: desenvolvimento de novas funcionalidades.
- `bugfix/*`: desenvolvimento de correções para problemas identificados.

Quanto à gerência de issues, o projeto adota a seguinte convenção para etiquetas:

- `documentation`: melhorias ou acréscimos à documentação.
- `bug`: uma funcionalidade apresenta problemas ou comportamento inesperado.
- `enhancement`: melhoria de uma funcionalidade existente.
- `feature`: implementação de uma nova funcionalidade.

### Ferramentas

As ferramentas empregadas no projeto são:

- Editor de código.
- Ferramentas de comunicação
- Ferramentas de desenho de tela (_wireframing_)

O editor de código foi escolhido porque ele possui uma integração com o
sistema de versão. As ferramentas de comunicação utilizadas possuem
integração semelhante e por isso foram selecionadas. Por fim, para criar
diagramas utilizamos essa ferramenta por melhor captar as
necessidades da nossa solução.
